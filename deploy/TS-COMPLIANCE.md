| Требование ТС | Статус | Как / чем |

| СУБД/кэш/пул без отдельного лицензирования | 🔵 | Postgres + Redis + pgbouncer (Apache/BSD/PostgreSQL-лицензии). |

## 5. Безопасность, аутентификация, RBAC

| Требование | Статус | Как / чем |

| Интеграция с внешним IdP (Keycloak/SSO) | ⏸ | ContextForge поддерживает нативно (`sso_keycloak_enabled` + маппинг ролей); брокер к этому готов (проверяет JWT, берёт `sub`). Отложено по согласованию. |
| RBAC, 4 роли (Админ платформы / Админ доступа / Бизнес-аналитик / Конечный пользователь) | ✅ | `provision-roles`: `mcp-platform-admin` / `mcp-access-admin` / `mcp-analyst` / `mcp-user` (least-privilege: конечный юзер только `servers.use`+`tools.execute`, без delete/create). Тесты в `test_bootstrap.py`. |
| Секреты (PAT/токены/пароли) в защищённом виде | ✅ | PAT — Fernet; секреты гейта — в его БД; ключ шифрования вне данных. |
| PAM удалённое администрирование | ⏸ | Инфра заказчика (не наш код). |
| **Структурированные логи + audit trail всех вызовов инструментов** | ✅⚙️ | **Брокер пишет per-call аудит «учётка ↔ инструмент»** (JSON-строка, точнее гейтового `/mcp` — видит и личность, и имя тула; тесты + живой лог). Гейтовые флаги (`AUDIT_TRAIL_ENABLED` и Ко) проброшены — включаются в `.env` (compliance-решение, каждый = DB-write). |
| Логи в доступном формате + retention | ✅⚙️ | Аудит — machine-readable JSON. `LOG_RETENTION_DAYS` (дефолт 30) проброшен в гейт. |
